# Results 2026-07-31 — PILLAR's DFD exports through the image adapter, three models

Six live conditions: **gpt-5.4 / gpt-4o-mini / grok-4.3** (Azure, one endpoint) × **two PILLAR
DFD exports**, all `vision_naive` + `grounded`.

Artifacts: `storage/derived/pillar_{authentication,enrollment}/image_vision-naive_<model>/run1/`
(DFD + `verification.txt`) and `storage/generated/.../run1/` (threats + `grounded_citations.txt`).
Index: `storage/generated/PILLAR_IMAGE_SWEEP.txt`.

**Why these two images matter.** Every image result the project has is on `kidstube/dfd.png`, a
matplotlib render *of* the `dfd.json` it is scored against — uniform strokes, machine-consistent
notation, a synthetic best case that `WEEK12_REPORT.md` flags as a ceiling measurement, not field
validation. These are a different tool's export of a different system: **dark theme**, trust-
boundary rectangles the canonical schema has no element type for, `DF_0`-style ids, a duplicated
element name, and a typo (`ML Moldel`) in a data store.

---

## 0. No gold standard exists, so no precision, recall or F1 is reported

Nobody has enumerated the privacy threats of PILLAR's face-authentication example. Authoring one
here would mean grading the pipeline against an answer key written by the thing being graded, so
`eval/run_eval.py` is never called. What *is* measurable without gold is what the thesis actually
rests on: whether each citation resolves, re-derived against the artifact it claims to come from.

## 3. The finding: models silently correct the diagram

The authentication and enrollment diagrams both label a data store **`ML Moldel`** — a typo in
PILLAR's export.

| model | authentication | enrollment |
|---|---|---|
| gpt-5.4 | `ML Moldel` (preserved) | `ML Moldel` (preserved) |
| grok-4.3 | `ML Model` (corrected) | `ML Moldel` (preserved) |
| gpt-4o-mini | `ML Model` (corrected) | `ML Model` (corrected) |

A model that writes `ML Model` has **silently edited the artifact it claims to be transcribing**,
and the pipeline cannot tell: the `bbox` citation still points at the right pixels, so
`citations_resolvable` and `region_has_content` both pass. `region_has_content` proves the box
landed on ink, never that the ink says what the model reported — exactly the weakness
`verify_vision.py`'s docstring declares, now with a concrete instance.

This is a **new failure mode, orthogonal to the ones the project has catalogued**. M3's open
citations pointed at real-but-imprecise source lines; Week 12's pixel boxes were real but in an
undeclared coordinate frame. Here the citation is *correct* and the transcribed content is wrong.
No verifier in the repo catches it, and closing it needs OCR over the cited box — the same
detector the closed-vocabulary argument keeps arriving at.

Note the direction: the "correction" is toward plausibility. That is what makes it dangerous —
it is invisible precisely where the analyst would not think to look.

## 4. The single-factor coordinate-frame recovery does NOT generalize

Week 12: KidsTube's boxes scored 0.54 as emitted and **0.98** after one global ×2.2 rescale — "real
but expressed in an undeclared coordinate system", fully recoverable in principle.

On a real export it does not recover:

| image | Mpx | aspect | box@emitted | isotropic | best scale | anisotropic (sx, sy) |
|---|---:|---:|---:|---:|---:|---:|
| kidstube (synthetic) | 3.59 | 1.21 | 0.54 | **0.98** | 2.20 | — |
| authentication / gpt-5.4 | 2.47 | 1.97 | 0.59 | 0.62 | 1.35 | 0.81 (1.05, 1.45) |
| authentication / grok-4.3 | 2.47 | 1.97 | 0.41 | 0.71 | 1.30 | 0.71 (1.30, 1.35) |
| authentication / gpt-4o-mini | 2.47 | 1.97 | 0.35 | 0.58 | 1.25 | 0.62 (1.60, 1.70) |
| enrollment / gpt-5.4 | 2.10 | 1.66 | 0.50 | **0.93** | 1.30 | 0.93 |
| enrollment / gpt-4o-mini | 2.10 | 1.66 | 0.46 | 0.77 | 1.25 | 0.77 |
| enrollment / grok-4.3 | 2.10 | 1.66 | 0.39 | 0.69 | 1.25 | 0.85 (1.10, 1.30) |

Two things follow, and they pull in opposite directions:

1. **Week 12's caveat #2 is confirmed** — the factor is not a constant. It tracks image size
   monotonically (3.59 Mpx → 2.2, 2.47 → 1.30–1.35, 2.10 → 1.25–1.30), consistent with a vision
   encoder resizing to a token budget. Per-image calibration, never a hardcoded number.
2. **But calibration no longer rescues the citations.** Isotropic recovery reaches 0.98 on the
   synthetic render and only 0.58–0.93 here. Letting x and y scale independently helps in three of
   six cases (gpt-5.4 authentication 0.62 → 0.81) and still never reaches the synthetic figure.

So the sharpened claim is *narrower and worse than Week 12's*: pixel citations are not merely in
an undeclared frame that one number fixes — on a real diagram a **meaningful fraction is simply
wrong**, and no global affine correction recovers them. Week 12 said calibration needs the detector
a closed vocabulary would have made unnecessary. This says calibration is **not sufficient even
then**.

The worst case is the crowded diagram: authentication (two overlapping labels, four boundary
rectangles) is below enrollment for every model on every measure. Same pattern as Week 12's
KidsTube endpoint errors — failures concentrate where the rendering is ambiguous.

## 5. Citation validity holds on an unfamiliar system

Five of six conditions are **1.00** on all three axes. The exception:

- **authentication / gpt-4o-mini: 0.97.** One threat of 34 cited `L.1.2`, which does not exist
  under `L` in the official v241203 trees. Caught by `generation/verify.py` with no model in the
  loop.

The pattern from `RESULTS_2026-07-28.md` repeats exactly: grounded citation validity is
structural but not absolute, the single failure came from the **smallest** model, and running only
a frontier model would have left it invisible. That it holds on two systems the knowledge base was
never tuned against is the result worth carrying into the writeup.

## 6. Two infrastructure findings, both fixed

**`region_has_content` could not fail on a dark diagram.** The verifier hardcoded `INK_THRESHOLD =
200` — "8-bit grey below this is ink" — which silently assumed dark marks on a light page. These
exports put **89.5%** of their pixels below that threshold (canvas grey 64), against 2.1% for the
KidsTube render, so with `INK_FRACTION = 0.005` every box passed, including one over empty canvas.
A check that cannot fail is worse than no check: it reports 1.00 and the 1.00 means nothing. The
background is now measured per image (modal grey) and ink is deviation from it. Light-background
images score **byte-identically** — the committed KidsTube figures (1.00 / 0.41 / 0.54 → 0.98 at
2.2) reproduce exactly.

**The Azure gateway 500s intermittently on image calls.** Measured on grok-4.3: 1 failure in 6
identical calls, always `Failed to reconstruct non-streaming response`, and the failing call ran
49s against 15–31s for the successes — a timeout wearing a 500. Per call that is survivable;
across a run it is not, because generation is one call per flow, so ~17% per call makes an 8-flow
run fail ~78% of the time. That is exactly what happened: six consecutive whole-run failures for
grok-4.3 whose eight flows all succeeded when retried individually. `AzureFoundryBackend` now
retries 5xx with backoff — narrowly, and a test pins the narrowness: a 4xx is a request this code
built wrong and must surface immediately, and **a model that answers badly is a result, never
something to re-roll until it agrees**.

## 7. Caveats

1. **n=1 per condition.** Point estimates. The vision arm's run-to-run variance is large and was
   observed again here: gpt-4o-mini's first authentication run returned **one** element, its second
   returned **eight**. That first run's artifacts were overwritten by the retry and are not
   recoverable; the table reports the second.
2. **No gold, so no P/R/F1** (§0). Threat *volume* differences (54 / 34 / 28) are not quality
   differences — on KidsTube volume tracked precision and recall in opposite directions.
3. **Trust boundaries are dropped silently.** Both diagrams draw four; the canonical DFD schema has
   no element type for them and no model tried to invent one. Whether that costs anything is
   unmeasured, and LINDDUN Pro does treat boundary crossings as relevant.
4. **The typo finding is n=2 diagrams, one token.** `ML Moldel` is the only mis-spelled label
   available to test on; the direction of the effect is clear, its rate is not.
5. **Both diagrams are small** (7–9 elements) next to KidsTube's 12. Nothing here says how the
   adapter behaves on a large third-party diagram.
